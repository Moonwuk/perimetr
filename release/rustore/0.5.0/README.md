Обновлено 5 октября 2026 года. **APK и AAB 0.5.0 собраны и подписаны; это офлайн-кандидат для проверки упаковки, не опубликованный релиз.** `onlineOrigin` и `privacyPolicyUrl` в проверенных файлах пусты. Установка на устройство, работа SDK и модерация ещё не проверены. Файлы [предыдущего комплекта](../builds/README.md) относятся к 0.4.1 и сохранены без подмены.

Проверенные параметры: `ru.moongametechnology.perimeter`, `versionName 0.5.0`, `versionCode 500`, Android 8.0+ (`minSdk 26`), `targetSdk 36`. Для отображения игры нужен актуальный Android System WebView с Chromium 111+. Кандидат подписан прежним ключом игры; ключ и пароли хранятся отдельно от репозитория.

## Состав кандидата

- Бот и дуэль на одном устройстве работают без интернета, локальный матч сохраняется.
- В текущем APK сеть отключена пустым `onlineOrigin`. Для следующей сетевой сборки выбран общий VPS: Node.js 24 + SQLite, который отдаёт веб-игру и API на одном публичном HTTPS origin. Android будет обращаться к этому же origin. Альтернативный Cloudflare backend сохраняется в исходниках; декларация должна соответствовать реально выбранному размещению.
- Подготовлены приватная комната по коду, открытая комната и автоматический поиск свободной открытой комнаты. Начало после готовности обоих игроков; создатель может закрыть комнату для обоих. Эти функции ещё нужно проверить в APK с настроенным сервером.
- Короткое нажатие выбирает карту; удержание и бросок на допустимую цель разыгрывают её. Длинные правила открываются отдельно, основной текст карты сокращён.
- Серверная статистика сетевых матчей и отдельные события перетаскивания рассчитаны на общую базу сервера: SQLite на VPS либо D1 при развёртывании Cloudflare. Очистка записей старше 30 дней выполняется планово. Текущий офлайн-кандидат не отправляет игровые метрики.
- Review SDK и Update SDK RuStore 10.5.1. Нет рекламы, платных карт, реальных платежей или push-уведомлений.

## Порядок завершения

1. Развернуть выбранный VPS backend Node.js 24 + SQLite, применить миграции и проверить постоянное хранение БД. Веб-игра и API должны обслуживаться одним сервером на **точном публичном HTTPS origin** без пути и параметров. Проверить `/api/health`, создание комнаты и начало матча двумя игроками. Указать тот же origin в `mobile/config.json`; CORS и Android allowlist должны разрешать только необходимые API. При выборе альтернативного Cloudflare backend проверить его D1 и миграции и обновить сведения о размещении.
2. Заполнить действительный контакт поддержки, имя/наименование ответственного за данные и публичный URL политики. Доработать `privacy-draft.html` под реальную обработку, опубликовать по HTTPS, указать URL в `mobile/config.json` и `store-listing.json`. Проверить ссылку внутри установленной игры.
3. После настройки URL пересобрать Android согласно [android/README.md](../../../android/README.md). Упаковка офлайн-кандидата уже проверена, но её результат не подтверждает новое содержимое. Проверить package, версии, манифест, сертификат `apksigner` и встроенные адреса; записать новые хеши отдельно. Не переименовывать старый APK в 0.5.0.
4. Пройти [device-test.md](device-test.md) на физическом телефоне и сетевой сценарий на двух устройствах. Снять минимум три кадра актуального приложения. Проверить данные SDK по фактическому сетевому поведению и итоговому манифесту.
5. В RuStore Console создать или обновить карточку. APK подходит для первого релиза; AAB также поддерживается, но требует настройки ключей подписи в консоли. Если версия 500 уже загружалась, предварительно выбрать следующий свободный `versionCode`.
6. Заполнить категории, маркировки контента и возрастную анкету по фактической игре; не угадывать рейтинг. Сверить заявленные сетевые функции с загружаемым APK и заново заполнить декларацию данных с учётом SDK.
7. Только после проверки сборки и материалов отправить версию на модерацию. SDK обновления/отзывов дополнительно проверить с версией, доступной через RuStore. Публикацию из этого комплекта автоматически не выполняли.

## Что пока не подтверждено

- Точный адрес рабочего сервера и доступность онлайн-игры из целевой сети пользователя.
- Имя/наименование ответственного за данные, контакт поддержки и опубликованная политика.
- Подписанная сетевая пересборка с фактическими origin и URL политики: текущая проверенная сборка оставляет оба поля пустыми.
- Установка и обновление на физическом телефоне, сетевой матч двух установленных приложений, сценарии RuStore.
- Актуальные Android-скриншоты, заполненная анкета и отправка в консоль.

Это перечень условий для выпуска, а не утверждение, что каждый пункт требует нового решения владельца. Уже подтверждённые данные и доступы используются повторно.

## Данные и аналитика

Сервер хранит состояние активной комнаты, включая название компании и скрытую игровую информацию; клиенту соперника передаётся только разрешённый обзор. Аналитическая таблица хранится отдельно: без имён, кода комнаты, токенов, расстановок и рук. Технический ID матча является псевдонимным; наличие хеша само по себе не доказывает полное обезличивание.

После развёртывания владелец может скачать JSON через `/?reports=1` с секретом `METRICS_EXPORT_TOKEN`. Этот секрет добавляется только в серверное окружение VPS (или секреты Worker при альтернативном размещении), не в публичные переменные или APK. Отчёт по умолчанию охватывает последние 30 дней, ограничен 100 матчами / 5000 событиями и сообщает об усечении. Хранение скачанных копий владелец определяет отдельно от автоматической очистки БД.

Для публикации нужно описать фактического хостинг-провайдера и RuStore, включая технические сетевые данные. Cloudflare указывается только если он действительно участвует в обработке, в том числе как прокси. Документы не подтверждают юридическое соответствие; правила RuStore отдельно требуют соблюдения применимых правил обработки и локализации персональных данных. Не отмечать «данные не собираются» лишь из-за отсутствия аккаунта или опасных разрешений Android. Наличие `analytics`/`metrics` в зависимостях подтверждено, но полный состав и момент передачи данных SDK на устройстве ещё не наблюдались.
