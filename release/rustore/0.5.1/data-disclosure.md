# Данные кандидата 0.5.1

Техническая заготовка для сверки с итоговым APK и консолью RuStore. Не подтверждает юридическое соответствие и не заменяет проверку реальных запросов SDK. Офлайн-кандидат 0.5.1 / 501 имеет пустые `onlineOrigin` и `privacyPolicyUrl`: собственная сетевая игра и игровые метрики в нём отключены. Онлайн-строки ниже описывают будущую сборку с настроенным сервером, а не наблюдавшиеся передачи текущего APK.

Выбранное направление размещения: общий VPS на Node.js 24 + SQLite для веб-игры и API; APK использует тот же публичный origin. Альтернативный backend Cloudflare D1 сохраняется в коде. В окончательной политике указать только фактически используемые хостинг, прокси, журналы и их настройки.

| Данные | Где и зачем обрабатываются | Хранение / удаление |
| --- | --- | --- |
| Локальная расстановка, карты, кредиты, ход и результат | WebView localStorage; продолжение бота или дуэли на одном устройстве | До замены сохранения или очистки данных Android; на игровой сервер не отправляются |
| Код комнаты и секрет места | На устройстве; восстановление сетевого места. Секрет передаётся API для авторизации, в БД комнаты хранится хеш | Удаляются при успешном закрытии/очистке данных; истёкший ключ не даёт доступ к комнате |
| Название компании / псевдоним | Передаётся игровому серверу и сопернику, хранится в состоянии комнаты | Комната доступна до 24 часов от создания; создатель может удалить её раньше. Истёкшие строки удаляются плановой очисткой |
| Полное состояние сетевого матча: расстановки, карты, действия, кредиты, результат | SQLite на выбранном VPS, либо D1 при альтернативном размещении; проверка ходов и синхронизация. Сопернику выдаётся только разрешённый обзор | До закрытия комнаты либо истечения её срока и ближайшей очистки |
| Сводка сетевого матча и события | Отдельные таблицы серверной БД: тип комнаты, статус, ход/раунд, первый игрок, победитель, доход/кредиты, карты, расходы, время, причины завершения/типовые ошибки | События старше 30 дней и сводки без обновлений 30 дней удаляются почасовой очисткой; возможна задержка до следующего успешного запуска |
| Броски карт | В сетевом матче клиент отправляет тип карты, submitted/cancelled/invalid и длительность жеста; оценка удобства интерфейса | Та же очистка серверной БД. Очередь только в памяти, очищается при смене комнаты; офлайн-события не отправляются |
| IP и технические сетевые сведения | IP используется сервером для ограничения частоты API; транспорт обрабатывается выбранным хостингом и настроенным прокси | Игровой код не записывает IP в таблицы комнат или метрик. Фактические access/error-логи, резервные копии, сроки провайдера и настройки прокси должен сверить владелец |
| Счётчик законченных матчей и время запроса отзыва | Android SharedPreferences; ограничение частоты Review SDK | До очистки данных приложения |
| Обновления и отзывы, технические сведения SDK | В сборке подтверждены Review/AppUpdate 10.5.1 и транзитивные `analytics 10.5.0`, `metrics 10.5.1`. Возможные технические данные включают пакет, версию, подпись и выполнение запросов; фактическая передача не проверена | По действительным условиям RuStore; состав полей, момент отправки и сроки сверить на устройстве и по документации SDK |

В метриках нет имени компании, открытого кода комнаты, токена, руки, колоды или расстановки. Вместо них — технический хеш ID матча и номер стороны 0/1. Не называть такой журнал гарантированно анонимным: это описание минимизации полей, а не юридическая оценка обезличивания.

Событие жеста `submitted` означает отправленную попытку разыграть карту. Подтверждённый ход фиксирует сервер отдельно. Ошибки аналитики не должны мешать игровому действию. Отчёты владельца ограничены по объёму; скачанные JSON находятся вне автоматической очистки серверной БД, и их срок/удаление нужно указать в окончательной политике.

## Сопоставление с полями RuStore

Сверить с актуальными названиями в консоли и реально загружаемой сборкой:

- «Имя»: название компании выступает сетевым псевдонимом. Не выбирать «не собирается», если эта функция включена.
- «Взаимодействие с приложением» / «Другие действия»: игровые действия, результаты, события перетаскивания.
- «Отчёты об ошибках» / «Диагностика»: только действительно передаваемые технические события; текущая игровая аналитика использует ограниченные типы ошибок, не сырые stack trace.
- «ID пользователей» / «Идентификаторы»: оценить по фактическим идентификаторам места/матча и полям SDK. Отсутствие регистрации не исключает технические идентификаторы.
- Данные всех SDK включаются в декларацию независимо от получателя. Автозаполнение по Android permissions не охватывает всё передаваемое приложением.

Игровые кредиты — условные счётчики матча, не банковские реквизиты, реальные покупки или кредитная история. Приложение не запрашивает email, телефон, контакты, камеру, микрофон, фото или геопозицию. Оно не содержит платежей, рекламы или рекламных SDK.

## Проверка манифеста и политики

В проверенном APK 0.5.1 присутствуют INTERNET, ACCESS_NETWORK_STATE, RECEIVE_BOOT_COMPLETED и внутреннее signature-разрешение DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION. Опасных runtime-разрешений, AD_ID и REQUEST_INSTALL_PACKAGES нет. RECEIVE_BOOT_COMPLETED присутствует в итоговом объединённом манифесте с зависимостями RuStore; это не доступ к личным файлам. Наличие разрешения или библиотеки не доказывает фактический состав сетевого трафика.

Проверка подписи, выравнивания, зависимостей и `lintRelease` выполнена для офлайн-кандидата, описанного в README. Сетевое наблюдение SDK, установка на эмулятор/физический телефон и проверка обновления через RuStore **не выполнены**. После настройки сервера/политики перепроверить итоговый манифест новой сборки.

Заполнить имя/наименование ответственного, контакт, цели и основания обработки, срок скачанных отчётов, порядок обращений и удаления. Проверить применимость требований к локализации для фактического хостинга и прокси. Политика должна быть доступна по HTTPS из карточки RuStore и внутри игры. Ссылка на общую политику RuStore не заменяет политику игры.
