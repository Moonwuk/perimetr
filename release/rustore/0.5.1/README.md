# КОНТУР 0.5.1 — подготовка онлайн-релиза RuStore

Срез 07.10.2026. Пользователь выбрал онлайн и офлайн. Версия: **0.5.1 / 501**, пакет `ru.moongametechnology.perimeter`, Android 8.0+, target API 36. Прежние кандидаты 0.4.1 и 0.5.0 не являются этой версией.

Включены изменения `main` до PR #16: стопки одинаковых карт ×N, перетаскивание без предварительного выбора, новые позиции элементов интерфейса. Сохраняются бот, дуэль на одном устройстве, комнаты, пауза по согласию и возвращение после обрыва связи. Review/Update SDK RuStore уже подключены; платежей и рекламы в игре нет.

**Онлайн-релиз заблокирован незаполненными публичными параметрами.** APK/AAB кандидата собраны и подписаны прежним ключом; подпись APK и выравнивание проверены, Android lint без ошибок. [Результаты и хеши](verification.md). Офлайн-кандидат подходит для проверки установки и управления; его нельзя выдавать за готовый сетевой релиз. Сборка не означает проверку на телефоне, загрузку в кабинет или прохождение модерации.

## Завершить настройку

Заполнить `publication-input.example.json` реальными значениями:

| Поле | Что указать |
| --- | --- |
| `onlineOrigin` | Публичный HTTPS origin игры/API, без пути, завершающего слеша и параметров |
| `privacyPolicyUrl` | Общедоступная HTTPS ссылка на заполненную политику |
| `supportContact` | Email поддержки или публичная HTTPS страница для обращений |
| `dataControllerName` | Имя/наименование ответственного за данные |
| `ageRating` | Результат анкеты RuStore: 0+, 6+, 12+, 16+ или 18+ |

Ни одно значение не выдумано. Владелец данных и итоговый рейтинг не выводятся из бренда студии или жанра игры. Политика должна описывать фактический backend и SDK; шаблон `privacy-draft.html` требует заполнения.

```sh
pnpm android:configure release/rustore/0.5.1/publication-input.example.json
pnpm android:check
export PERIMETER_SIGNING_FILE=/absolute/private/path/signing.properties
pnpm android:release
```

Настройщик проверяет все поля до записи и синхронизирует конфиг APK с карточкой. `android:release` останавливается при неполной конфигурации. `android:candidate` — явная команда для подписанной проверочной сборки; публикационную проверку она не заменяет. Прямой запуск Gradle также требует ручной проверки `android:check` перед отправкой в магазин.

Для GitHub Actions передать тот же JSON в поле `publication_json` ручного workflow **Android RuStore release**. Ключ остаётся в существующих секретах `PERIMETER_*`; JSON содержит только публичные параметры. Workflow не отправляет приложение на модерацию.

## Комплект карточки

- `store-listing.json` — подготовленное описание **будущей сетевой сборки**, ещё не разрешение публиковать офлайн-кандидат.
- `privacy-draft.html` — проект политики; оставить фактический способ размещения (VPS или Cloudflare), заполнить владельца и контакт.
- `data-disclosure.md` — карта данных и разрешений для сверки с APK. INTERNET/ACCESS_NETWORK_STATE не означают доступ к фотографиям, файлам, камере или микрофону.
- `device-test.md` — короткая обязательная проверка установленной версии.
- `verification.md` — фактически выполненные проверки и хеши кандидата.
- `../icon-512.png` — существующая иконка 512×512. Проверить визуально перед загрузкой.

Минимум три скриншота снять в установленном актуальном APK: меню, расстановка, матч. Старые browser-превью из `../previews` не подтверждают вид 0.5.1.

## Перед модерацией

1. Развернуть выбранный сервер с постоянной БД, проверить `/api/health` и Android CORS. Сетевая версия APK должна использовать этот проверенный сервер.
2. Заполнить и опубликовать политику; синхронизировать пять публичных полей командой выше.
3. Пересобрать, проверить прежний сертификат, увеличенный versionCode и встроенные URL. Если 501 уже занят в RuStore, выбрать следующий свободный номер до сборки.
4. Проверить установленный APK, два Android-устройства и Android ↔ веб. Снять актуальные скриншоты.
5. В кабинете загрузить APK, описание, иконку и скриншоты; сверить декларацию данных, контакт, категории и возрастную анкету. Отправить на модерацию после выполнения этих пунктов.
