# Общие метрики тестирования

Метрики сетевых матчей хранятся в той же Cloudflare D1, что и комнаты, в отдельных таблицах `metrics_matches` и `metrics_events`. Закрытие комнаты сохраняет её итоговую запись. Локальные матчи с ботом и на одном устройстве сюда не отправляются.

## Включение и выгрузка

1. Опубликуйте обновлённый Worker через `pnpm cf:deploy`: команда применит миграции `0002_bent_garia.sql` и `0003_warm_revanche.sql` перед публикацией.
2. В Cloudflare откройте **Workers & Pages → perimetr → Settings → Variables and Secrets → Add**. Выберите **Secret**, имя `METRICS_EXPORT_TOKEN`, значение — собственный случайный ключ не короче 32 символов. Сохраните через **Deploy**. Это секрет работающего Worker; в параметры сборки и `VITE_*` его добавлять не нужно. [Инструкция Cloudflare](https://developers.cloudflare.com/workers/configuration/secrets/#via-the-dashboard).
3. Откройте адрес игры с `/?reports=1`. Введите тот же ключ в поле «Ключ владельца» и нажмите «Скачать отчёт».
4. Передайте полученный `contour-playtest-YYYY-MM-DD.json` для анализа. Сам ключ передавать не нужно. Он не включён в JSON, не хранится браузером приложения и сбрасывается при закрытии окна отчётов.

Ключ защищает только выгрузку. Сервер начинает собирать события сразу после применения миграций и публикации кода. Настройки чужих устройств не нужны.

## Содержимое

| Источник | Данные |
| --- | --- |
| Сервер | Создание и подключение, подтверждённые действия, тип карты, расходы кредитов и действий, чистое изменение денег, ошибки игровых запросов |
| Сводка матча | Открытая/закрытая комната, номер реванша, первый игрок, раунд, деньги и доход обеих сторон, победитель, статус, время и причина завершения |
| Клиент | Перетаскивание карты: попытка разыграть, отмена или недопустимая цель, длительность жеста |

`source: "server"` обозначает подтверждённые сервером события. `source: "client"` — диагностические сведения: `submitted` означает отпущенную на допустимой цели карту, но само по себе не подтверждает успешный ход. Успешное действие записывается сервером отдельно. Ошибка сбора не должна отменять игровой ход.

`moneySpent` — цена карты или базового действия. `moneyDelta` — изменение баланса; например, у подмены платежа к расходу добавляются похищенные кредиты. Эти значения намеренно различаются.

Имена игроков, исходные коды комнат, ключи доступа, руки, колоды и скрытые расстановки в метрики не записываются. Стороны обозначены числами 0 и 1, матчи — непрозрачными идентификаторами.

## Ограничения

- Срок хранения — 30 дней; плановая очистка запускается каждый час. Незаписанные из-за сбоя события не восстанавливаются задним числом.
- JSON содержит до 100 матчей и 5000 последних событий выбранных матчей. `truncated: true` означает неполную выгрузку; интерфейс показывает предупреждение.
- За меньший период можно запросить `GET /api/metrics/export?since=<ISO>&until=<ISO>` с `Authorization: Bearer <ключ>`. Интервал должен входить в последние 30 дней. Ключ нельзя помещать в URL.
- Клиент отправляет только диагностические события сетевого матча, небольшими пакетами; очередь ограничена и не сохраняется на устройстве. При потере сети часть жестов может отсутствовать.
- Длительность брошенной партии приблизительная: если комнату явно не закрыли, сервер отмечает её истёкшей при очистке. Незаконченный матч имеет длительность до последнего записанного события.
- Это данные для тестирования механик и интерфейса. Число сыгранных карт само по себе не доказывает их силу: нужно учитывать первый ход, раунды, расходы и исход матча.

## Проверено локально

Два независимых браузера и настоящий локальный Worker + D1: открытая комната, автоматическое подключение, готовность обоих участников, один ход перетаскиванием, серверная запись расхода, клиентская диагностика, закрытие для обоих, скачивание JSON по ключу. Отдельно проверены отказ без ключа, недоступность выгрузки без настройки, конкурентные ходы, отказ хранилища метрик и лимит D1 при экспорте 100 матчей. Проверка в аккаунте Cloudflare владельца и на физических телефонах остаётся отдельным этапом.
