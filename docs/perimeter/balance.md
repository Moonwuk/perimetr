# Баланс: проблемы, гипотезы, проверки

## Статус

Это план исследования, не результат нового прогона. В текущем PR нет симулятора, исходных логов или подтверждённой выборки матчей. Числа из прежних сообщений нельзя считать воспроизводимой базовой линией без версии правил и данных эксперимента.

## Что сообщил пользователь

| Наблюдение | Что нужно воспроизвести |
| --- | --- |
| Приходили только атакующие карты, которыми нельзя воспользоваться | Сколько ходов рука не даёт полезного действия и какие предусловия блокируют карты |
| Атаки ощущались слишком слабыми | Соотношение цены атаки, потерянного дохода соперника и упущенного собственного развития |
| На телефоне не видно карту целиком | Не связана ли часть ошибок выбора с невозможностью прочитать условия и эффект |
| Предложена логика «камень — ножницы — бумага» | Даёт ли подходящая контрмера заметную выгоду без универсальной неуязвимости |

Первые три пункта — пользовательская обратная связь, последний — одобренное направление изменений. Это не подтверждение их реализации.

## Основные гипотезы

**Атака должна конкурировать с развитием.** Для экономического варианта учитывать не только прямой эффект, но и потерянный соперником доход за срок проблемы, его стоимость ответа и собственную цену упущенного экономического хода.

**Защита должна окупаться против соответствующей угрозы.** Универсальная дешёвая защита может обесценить атаки; дорогая и слишком узкая может почти никогда не быть правильным ходом. Контрмеры проверяются по всей матрице взаимодействий.

**Неудачная рука не должна лишать игрока участия.** Базовые действия, обмен и изменение предусловий — разные способы решения; сравнивать их отдельно, иначе трудно понять, какое изменение помогло.

**Лидер должен оставаться уязвимым для решений, а не для скрытой подстройки.** Проверять возможность догнать лидера через успешные действия. Автоматическая помощь проигрывающему в обсуждении не утверждалась.

Эти положения — гипотезы дизайна, не доказанные свойства прототипа.

## Матрица стратегий

Для экономического режима предлагается сравнить агрессивную, защитную, экономическую и смешанную стратегии. Для каждой пары менять первого игрока и набор случайных исходных данных.

Возможное ожидаемое направление: давление мешает жадному развитию, профильная защита сдерживает давление, умеренное развитие обгоняет избыточную защиту. Это гипотеза для анализа архетипов, а не замена конкретной матрицы атак и контрмер и не обещание строгого цикла побед.

Для тактического варианта измерять выполнение задач, удержание работоспособности и доступность маршрутов атаки. Не сравнивать его очки напрямую с денежным результатом экономического режима.

## Что сохранять в отчёте

| Метрика | Зачем нужна |
| --- | --- |
| Версия правил, код, набор карт, seed | Позволяет воспроизвести матч |
| Кто ходил первым и какие стратегии играли | Отделяет преимущество старта от преимущества стратегии |
| Исход и длительность | Показывает перекосы и затянутые партии |
| Ходы без полезного действия | Проверяет проблему неудобной руки |
| Розыгрыши и отказы по каждой карте | Выявляет бесполезные карты и слишком тяжёлые условия |
| Доход, расходы и потери по ходам | Объясняет результат экономического режима |
| Применённые контрмеры и остаточный эффект | Проверяет понятность и силу взаимодействий |
| Возвраты после разрыва соединения | Отделяет сетевой дефект от проигрыша по правилам |

Процент побед сопровождать числом матчей, долей ничьих и неопределённостью оценки. Маленькая выборка или примитивный бот не доказывают баланс между людьми.

## Порядок экспериментов

1. Получить исходники и зафиксировать неизменённую базовую конфигурацию.
2. Воспроизвести конкретную пользовательскую проблему.
3. Изменить одну группу параметров и повторить сравнимый прогон со сменой сторон.
4. Сохранить улучшения вместе с компромиссами, проверить регрессию остальных карт.
5. Провести короткие человеческие тесты на компьютере и телефоне.

Порог приемлемого преимущества первого игрока, целевая длительность, объём выборки и желаемая частота обмена карт пока не утверждены. Не выдавать произвольный процент побед за критерий готовности.

## Обязательная корректность до обсуждения тонкого баланса

Предлагаемые регрессионные сценарии: недопустимое действие не меняет состояние; затраты списываются один раз; эффект истекает в определённый момент; повтор команды не создаёт второе действие; победа проверяется по правилам выбранного режима; скрытая рука не попадает к сопернику; разрыв связи не восстанавливает потраченные ресурсы.

Исполнение этих тестов в текущем PR не заявляется.
