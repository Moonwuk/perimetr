# Карты и обучающий слой

[К оглавлению](../../README.md)

## Статус каталога

Это восстановление требований и примеры для следующей итерации дизайна. Это **не экспорт ранее описанного каталога из 14 карт**. Идентификаторы, названия, стоимость и эффекты реальных карт должны быть перенесены из исходников прототипа отдельно.

## Три категории

Для экономического варианта пользователь выбрал **атаку, защиту и экономику**. Разведка и вспомогательные эффекты могут быть функциями карт внутри этих категорий; четвёртая обязательная категория этим документом не вводится.

Для тактической дуэли отдельно обсуждалось, что карты дополняют всегда доступные базовые действия. Это правило ещё нужно сверить с экономическим прототипом, а не объявлять автоматически существующим в нём.

## Схема описания карты

Предлагаемые поля для единого источника правил:

| Поле | Что фиксировать |
| --- | --- |
| Идентификатор | Стабильный внутренний ID, не зависящий от языка |
| Название и категория | Что видит игрок и к какой из трёх категорий относится карта |
| Стоимость | Очки действий, деньги и иные явно выбранные затраты |
| Условия | Фаза, тип цели, необходимые сведения или доступ |
| Эффект | Точное изменение состояния и момент применения |
| Длительность | Когда эффект начинается, истекает и может ли суммироваться |
| Контрмеры | Какие защиты и ответы меняют результат |
| Объяснение | Термин, смысл механики и границы игрового упрощения |
| Видимость | Какие сведения становятся известны каждому участнику |

## Примеры для проработки, не утверждённые карты

| Рабочее название | Категория | Предлагаемая игровая роль |
| --- | --- | --- |
| Разведка | Атака | Получить ограниченное знание о допустимой цели |
| Перегрузка сервиса | Атака | Временно уменьшить доход выбранного сервиса |
| Компрометация доступа | Атака | Подготовить дополнительное действие против подходящей цели |
| Нарушение работы приложения | Атака | Создать проблему, требующую профильной контрмеры |
| Фильтрация | Защита | Ослабить определённый тип атак, но не все атаки сразу |
| Усиленная проверка доступа | Защита | Затруднить определённую ветку атак на доступ |
| Обновление | Защита | Снять или предотвратить явно обозначенную проблему |
| Восстановление | Защита | Вернуть работоспособность с понятной ценой и ограничениями |
| Развитие сервиса | Экономика | Увеличить будущий доход, потратив ресурс сейчас |
| Контракт | Экономика | Получить экономическую выгоду при соблюдении условия |

Все соответствия — игровые предложения. Из них нельзя выводить, что одна реальная мера безопасности предотвращает любой инцидент с похожим названием. Численные параметры намеренно не выдуманы вместо потерянного исходного каталога.

## Неудачная рука

Пользователь сообщил, что получал одни атакующие карты и не мог ими воспользоваться. Для проверки предлагаются три подхода: полезное базовое действие без карты, ограниченный обмен и более мягкие предусловия для части атак.

Это альтернативы для эксперимента, а не три одновременно утверждённых изменения. Проверять, остаются ли важными подготовка и защита, не возникает ли бесплатного перебора колоды и не становится ли одна карта универсальным ответом.

## Обучение без остановки партии

Предложенный слой: нажатие на термин открывает короткое объяснение. Полный текст карточки доступен отдельным раскрытием и на телефоне, без наведения мыши.

Объяснение содержит четыре части: что означает термин, как он представлен в этой игре, почему сработало действие и чего упрощённая модель не отражает. Послематчевый разбор может связывать решения с ключевыми потерями дохода или выполненными задачами; это предложение, не готовая функция.

Не требовать от новичка знать конкретные инструменты. Не превращать карту в инструкцию по атаке внешних систем: для игровой механики достаточно абстрактных целей, условий и последствий.

## Проверка карточек

У каждой карты есть допустимый сценарий применения и понятная причина отказа. Игрок видит затраты до подтверждения. Недопустимое действие не списывает ресурс. Суммирование одинаковых эффектов определено явно. Скрытые свойства цели не раскрываются случайно через текст ошибки или прогноз урона.
